# U2b.9 site map — LocalWave call sites for U3 / U4a / U4b

Purpose: one row per LocalWave UI site that U3/U4a/U4b migrate, giving the exact target so the migration needs no design
decision. HEAD: `6c75459` (branch u2b). File:line is the working tree at that HEAD, paths under `crates/lw_ui/src/shell/`
unless noted. Audit ids (`#n`, `Nn`) are `docs/dx-checkpoint/widget_reuse_audit.md` and plan §11; its line numbers are stale.

Columns: **id** · **file:line** · **current** · **target** (Rust as it will be written against the shaped API; no open gaps) · **style** (named const in `shell/theme.rs`, one-line definition) · **body** (`localwave-*` name / variant, or
built-in) · **a11y** (role, name, states/actions after migration) · **D9** · **step**.

Conventions: `v::X` = `theme::variant::X: u16` (the localwave-* body variant ids, registered once by `register_bodies(ui)` in
`shell/theme.rs`, replacing `crates/lw_ui/src/commands.rs:19-22`). `ic(I)` = `icon_drawing(Icon::I)`; new app icons needed:
`Icon::Add`, `Icon::Offline`, `Icon::Kept`, `Icon::RepeatOne`, `Icon::Grip` (and `draw_icon` must honour the rect it is given
so `Button::icon_size` scales it). `lit(a,b)` is the existing theme.rs helper. Intents after `=>` are unchanged unless noted.

D9 legend (fingerprint diffs expected): **F** focus on press vs click · **S** enabled/disabled/checked/selected bits ·
**R** the widget's own role · **N** names/values the widget formats · **T** focus/tab order inside one widget · **none**.

### Selection model (#15, #27, #80, controller)

LocalWave's selection (shell.rs:48-51, :198-249, :312-319) maps onto `ListState` as follows; no new pxui item is needed, the
re-map by id stays app work on delivery (never per frame).

- State: `marked: Vec<usize>` + `anchor` become `song_rows: RefCell<ListState>` (one flag byte per displayed row, `anchor` =
  `ListState::anchor`); `selected: Option<usize>` stays (the keyboard/menu row). Frames hold `&ShellState`, so they borrow it
  mutably only around the `selection_list` call (as the `Cell` fields today); `apply`/`refresh` use `get_mut()`. The songs list's
  heading has its own `song_table: RefCell<TableState>` (its `selection` unused), so the header callback never re-borrows `song_rows`.
- Widget writes: `ListResponse::selected` is set on every widget change of the flags (click, Command-toggle, Shift-range, Space,
  key move, Command-A), so the songs list emits `Intent::Selected(i)` (replacing `SelectRow`/`Select(Toggle|Range)` from clicks);
  apply sets `selected = Some(i)` and bumps `selection_revision`, which keys `library_revision` as today. The per-row
  `song-visual` view drops `marked` from its revision (the row body draws SELECTED from `CellState`).
- App writes (compact select mode #27, menu Select All, shortcuts outside the list) keep `select(Selection)` on the same flags,
  sizing first (`if rows.len() < len { rows.resize(len, 0) }`): Toggle `rows[i] ^= SELECTED`, Range `fill(0)` then
  `anchor..=i`, All `rows.clear(); rows.resize(len, SELECTED)`, Clear `fill(0); anchor = None`, Move sets the flag and
  `reveal_selected` → `ui.reveal(&r.handle, i)`. `is_marked(i)` = `rows.get(i).is_some_and(|f| f & SELECTED != 0)`.
- Re-map on reload, worker sort and query change (all arrive through `refresh` with the worker's `catalog.remap`), replacing
  shell.rs:312-319, bounded and allocation-free in steady state (a kept scratch `Vec<u8>` swaps with `rows`):

  ```rust
  // read what the map needs before borrowing the flags: `song_rows` and `remap_scratch` are then borrowed as disjoint fields
  let (query, len) = (self.query, self.collection(next_catalog).map_or(0, |c| c.rows.len()));
  let map = |i: usize| remap.resolve(old, Some(i), query).1;
  let list = self.song_rows.get_mut();
  if self.route != Route::Files && (list.anchor.is_some() || list.rows.iter().any(|f| f & ListState::SELECTED != 0)) {
      let mut next = std::mem::take(&mut self.remap_scratch);
      next.clear();
      next.resize(len, 0);
      for (i, f) in list.rows.iter().enumerate() {
          if f & ListState::SELECTED != 0 && let Some(j) = map(i).filter(|&j| j < next.len()) { next[j] = ListState::SELECTED }
      }
      self.remap_scratch = std::mem::replace(&mut list.rows, next);
      list.anchor = list.anchor.and_then(map);
      self.selection_revision = self.selection_revision.wrapping_add(1);
  }
  ```

  One pass over at most 10,000 flag bytes per delivery; `resolve` runs only for selected rows (as it does for `marked` today).
- The marked count and the first marked index (the "N selected" header, actions on the first selected song) are kept by the app
  beside the flags (`song_marks: (usize, Option<usize>)`), updated where the flags change (the `Intent::Selected` apply, `select`,
  the remap above) by one pass over the flags at that moment, never by scanning `rows` per frame; pxui reports only that the
  selection changed (`ListResponse::selected`).
- A click that changes a selection list's selection builds the frame again before it is drawn, and only the first build reports
  it (`ListResponse::selected`/`activated`/`secondary`; the second build's response is empty). Every LocalWave caller writes its
  intent only when the response names something (`if let Some(i) = r.selected { *intent = Some(Intent::Selected(i)) }`), never
  `*intent = r.selected.map(..)`, so the repeated build cannot clear it: songs #15, the sidebar lists (navigation on `selected`),
  queue #16, folders #80's select mode where it uses `selection_list`, and the playlist pickers.
- Controller: `selected_song_ids` (actions.rs:194, :664, :701; shell.rs:811, :823) becomes
  `rows.iter().enumerate().filter(|(_, f)| *f & SELECTED != 0).filter_map(|(i, _)| ids.get(i).copied())` collected into the
  `Vec<i64>`/`Arc<[i64]>` the callers already build (action time, not frame time). `selected_folder_songs` reads `folder_marks`.
