# DX1.12 public-surface audit (pxui origin/rust-port 6ab2bf7, crates/public/pxui + pxui_types)

Read-only audit against api_spec.md / brief_review.md. Line numbers are from `git show origin/rust-port:<path>` (paths below are under crates/public/). "ABI" = changes a C export, a repr(C) record or a C-visible number; "Rust-only" = wrapper/type shape only. Theme-file key renames are a file-format change, flagged separately.

Notes items dropped as already fixed: DialogButton text is already `<'a>` (pxui_types/src/ui.rs:397-420); pxui_types doctests are already split by module in the gate (pxui/tools/gate/src/main.rs:1452-1470, DX6.0a); TextInputOptions fields are already private with const builders (only the u32 codes remain, finding 21); `pxui_ui_context_menu` has_selected/selected/lead_from stays an accepted DX7 freeze note.

### Batch A  Text/label style values (files: pxui_types/src/text.rs, pxui/src/text.rs, pxui/src/author/text.rs, pxui_types/src/ffi.rs only for the Label -> PxuiLabelStyle conversion)

1. pxui_types/src/text.rs:72-110, :46-58. `Label` fields `wrap: u32`, `ellipsis: u8`, `align: u32`, `features: u32` are magic codes (`TextStyle::WRAP_*`, `ELLIPSIS_*`, `ALIGN_*` consts, themselves undocumented: text.rs:46-58). Fix: `enum Wrap {None, Word, Glyph, WordSpaces}`, `enum Ellipsis {None, End, Middle, Head}`, `enum TextAlign {Start, Center, End}` (repr(u32)/u8 with the same numbers), `Label` stores them; `TextStyle` (the shaper record) keeps the C numbers via `From`. Builders `.wrap()`, `.wrap_spaces()`, `.ellipsis()`, `.center()`, `.end()` stay; add `.wrap_glyph()`, `.ellipsis_middle()/_head()`, `.tabular()` (replaces public `features`). ABI: Rust-only (Label is not repr(C); conversion keeps C numbers).
2. pxui_types/src/text.rs:72-110, :111-351. `Label` has all-pub fields, so `Label { size: Some(..), ..Label::BODY }` is possible and the repo itself does it (pxui/src/surface.rs:11-14 `label_of`), and no builders exist for `caps`, `pad`, `features`, `max_lines` is spelled `.lines`, `font` takes a raw `u16`. Fix: make fields `pub(crate)`; add `.caps()`, `.pad(f32)`, `.tabular()`, keep `.lines`; document why `font(u16)` (family index) or give it a `Family` newtype. ABI: Rust-only. Remove `label_of` from surface.rs (test helper; belongs to Batch H).
3. pxui_types/src/text.rs:141-351 naming: `Label::center()` sets text alignment, `Node::center()` centres children, `Button::centered()` centres content; `Label::grow()` and `Segmented::grow()` take no argument while `Node::grow(share)` takes an f32; `Label::h(points)`/`w(Size)` mix a point and a `Size` (Node has `w(Size)` + `w_px(f32)`). Fix: one rule across Node/Label/Button/IconButton/Segmented/Menu/Toggle: `w(Size)`/`h(Size)` + `w_px`/`h_px`; `grow()` no-arg means share 1, `grow_by(f32)` the share; alignment builders `align_start/center/end`. ABI: Rust-only.
4. pxui/src/text.rs:99-483 and pxui/src/paint.rs (see Batch B). Two style types reach the text API: `Text::measure/width/rasterize_rgba/quads` and `Paint::text_spans/text_metrics` take `TextStyle` (shaper record, raw `u32` codes, `size_points`), while `UiText::text_spans/text_line_box`, `Ui::label*` and `Paint::text_styled/text_chars` take `Label`. Third form: `text_width(size: Option<i64>, s)`, `caret_x(size: Option<i64>, ..)`, `selection(size: Option<i64>..)`, `Ui::text_width`, `Ui::text_top(size)`. Fix: one style input, `Label` (resolved via `UiText::resolve`), with `TextStyle` kept only as the `resolve` output / C record; make `TextStyle` fields `pub(crate)`-or-builder. ABI: Rust-only wrappers; C `pxui_text_*` exports unchanged.
5. pxui/src/text.rs:190-226 vs :415-470. `Text` and `UiText` duplicate `measure/measure_spans/width/rasterize_rgba/add_font/enable_system_fonts` verbatim (two impls). Fix: one trait or one type (`UiText` derefs to the backing) so a method exists once. `Text::new -> Option`, `Text::add_font -> Option<u32>` vs `enable_system_fonts -> Result<(), Error>`: pick `Result<_, Error>`. ABI: Rust-only.
6. pxui/src/author/text.rs:77-114. `label`, `label_fmt`, `label_digits` return `Handle` (PxuiBox) while every other leaf returns Response; the brief_review DX4 trial lists "ui.label returning Handle" as a gap. Fix: keep leaf-without-key per spec but return a `Handle` newtype-free `PxuiBox` is fine only if documented; add `label_of(...)`? Decide in the row: spec says labels are leaves, so `Handle` stays and `Response` is not required; document it in the module docs (author/mod.rs). ABI: none.
7. pxui/src/text.rs:41 `pragmasevka()` is a product-specific font accessor in the public API of a UI kit. Fix: move to the app/gallery or document as the bundled fallback; undocumented `pub fn` ones in this file: none. ABI: none.

### Batch B  Paint (files: pxui/src/paint.rs, pxui/src/image.rs, pxui/src/images.rs)

8. paint.rs:247-270. ABI: Rust-only if the `pxui_paint_*` exports are kept as they are (the shape trait in pxui_types/src/shape.rs:98 stays).

10. paint.rs:184, :191, :160, :192, :211, :234-240. Text methods use four shapes (see finding 4): `text_spans(&TextStyle, width, color: Option<Rgba>, text, spans)` has an `Option<Rgba>` colour while `text_styled` colours through the `Label`; `text_width(size: Option<i64>)`; `cap`, `cap_width`, `ratio`, `input_region`, `label_size`, `cap_tracking`, `text_top(size)` are widget-internal helpers exposed publicly (undocumented: paint.rs:160,191,192,238,239,240). 11. paint.rs:31-45. `Paint` has pub fields `theme, font_size, row_height, density, rtl` (undocumented, :39-43) next to methods that read them (`color`, `label_size`). Fix: private fields + documented getters. ABI: Rust-only.
12. image.rs:35 vs :58. `Ui::image(label: &str, ..)` panics on an invalid `Image`; `Paint::image/image_fit` silently draw nothing. One rule: an invalid descriptor is a caller bug, so both should report the same way. Fix: `Ui::image` returns `Response`/`Handle` and never panics on a bad `Image` (draws nothing, like Paint), keeping panics for outside-a-frame only; or both panic. Recommend "silent" because `Image` is host-owned and can go bad between frames. Also `Ui::image` takes `label: &str` as identity (no Key) and 5 positional args (`Fit`, `Size`, `Size`): becomes `ui.image(key, &image, &ImageStyle::DEFAULT.fit(Fit::Contain).size(w, h))` with `ImageStyle` Copy const-builder. `Paint::image_fit(x, y, w, h, image, fit, tint)` 7 positional becomes `paint.image(rect, &image, ImageFit::..)`. ABI: Ui::image changes `pxui_ui_image` only if the "no panic" semantics move into the engine; otherwise Rust-only.
13. images.rs:534-552 BUG (still present): `Images::insert` writes `by_id.insert(key.id, index)` without clearing an older slot holding the same id; a later `remove(older_slot)` (images.rs:586) deletes `by_id[id]` and drops the new mapping. Fix: when `by_id` already maps `key.id` to a different slot, remove that slot first (and document). Rust-only. Add a regression test.
14. images.rs:237-260 `configure` bumps `revision` but drops nothing (doc now says so); `Tokens`-style doc fix is done, behaviour unchanged. Keep as documented; drop from notes.
15. images.rs (module). Slot API leaks into the public surface: `insert(index, key, image)`, `index(id)`, `oldest()`, `remove(index)`, `last_used(index)`; `Request::insert(id, path, max_pixels) -> bool` and `Images::insert(index, ..)` share a name for different jobs; `images::Key` and `images::Path` collide in name with `pxui::Key` (author) / `std::path::Path`; `get` / `get_at(.., node)` and `requests` / `visible_requests` are twin pairs. Fix: `Images::store(id, image)` (hides the slot choice: oldest-eviction inside), rename `images::Key` -> `images::Want`, `Path` -> `ImagePath`; `get(id, path, points)` + `get_in(node, ..)` merged by an optional `node` in the call's `Place` argument; `requests` takes `Option<&Ui>`. ABI: Rust-only (no C exports in images.rs).
16. images.rs:41-60 `Path::new -> Option<Self>` silently truncates/rejects (documented), `Images::insert` panics on `index >= CAPACITY`: mixed policy; one rule (Option/bool, never panic for data; panic only for programmer index) to be stated in module docs. Rust-only.
